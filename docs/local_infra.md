# Local Infrastructure

## Зачем нужен этот слой

Для проекта **F1 Data Warehouse + Analytics Website** локальная инфраструктура нужна, чтобы запускать сервисы проекта не вручную на Windows, а в изолированной среде через Docker Compose.

На текущем этапе мы поднимаем **MinIO**.  
Он нужен как **локальный S3-compatible storage**, то есть как raw-слой нашего Data Lake.

Через него поток данных в проекте будет выглядеть так:

`F1 API -> Python ingestion -> MinIO (raw) -> transform -> Oracle DWH -> ClickHouse -> backend -> website`

## Роль MinIO в проекте

MinIO используется как хранилище сырых данных.

Что это значит в контексте проекта:
- Python ingestion будет забирать данные из F1 API
- исходные ответы API будут сохраняться в MinIO
- raw-данные будут храниться отдельно от трансформированных слоев
- это позволит:
  - повторно прогонять трансформации,
  - не ходить в API каждый раз заново,
  - сохранять исходное состояние данных,
  - строить пайплайн более похоже на реальный DE-подход
